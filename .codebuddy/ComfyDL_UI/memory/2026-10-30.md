## 白屏竞速根治 + 模板视图规范化（2026-10-30 批次 2）

### ① 非 InPrivate 间歇白屏（用户实测日志 → 根因 → 修复）

- **根因（chunk 逆向实证）**：官方 settings store（`settingStore-KkBYyEnh.js`）的 `load()`
  开头断言 `if (Object.keys(t.value).length) throw Error("Setting values must be loaded
  before any setting is registered.")`；而官方 `registerExtension()` 对扩展对象的
  `settings` 数组是**立即处理**（非 setup 时）。我们的 profiler/crashsite/motion 三模块在
  `waitFor(comfyAPI)` 后抢跑注册 → 与 `loadAuthenticatedStores` 竞速 → 输了则 load() 抛
  未捕获错误 → store bootstrap 链中断 → **整页白屏**。InPrivate（无缓存/无用户数据）时序
  不同所以多数时候不炸。
- **修复（官方范式）**：三模块 registerExtension 前等待 `app.extensionManager.setting
  .isReady === true`（pinia store 暴露的就绪信号；load 完成后才注册，空值档案也不卡）。
  profiler.js/motion.js 的 `start(force)` 加 gate + 30s 超时降级（超时 register anyway，
  退化为旧行为）；crashsite.js 在注册循环前一次性 waitFor gate。settingsStoreReady()
  helper 三处同款；profiler.js 无 TAG 常量（用字面量前缀），motion.js 有。
- **关键逆向事实**：`app.extensionManager.setting`（单数）= settings pinia store 本体
  （app 内部自用 `Q.extensionManager.setting.get(...)`），暴露
  `{settingValues, settingsById, isReady, isLoading, error, load, addSetting, set, ...}`；
  `app.ui.settings` 是 ComfySettingsDialog（dispatchChange/addSetting/getSettingValue 委托 store）。
  extensionManager 在 App 组件 setup 时赋值（`ve.extensionManager=U()`），此时 pinia 已激活。

### ② 启动模板偏小/贴边/超界（用户截图）

- **根因**：模板 JSON 的 `extra.ds`（导出时烘焙的画布视图）= scale 0.4-0.5 + offset [0,0]，
  loadGraphData 会应用该视图。
- **修复**：一次性脚本按包围盒自适应规范化全部 7 个模板：scale = min(0.72, 1550/w, 880/h)
  （下限 0.35，round 2dp），offset [40, 50]（给原点节点留边距防顶栏遮挡）。
  实测：classification 0.72 / LM_load 0.72 / LM_train 0.64 / linreg 0.72 /
  regression_reuse 0.72 / tabular_clf 0.72 / tabular_reg 0.6。
  `regression_model_reuse.json` 带 UTF-8 BOM（保持原样）。
