## 5. 【战略构想】ComfyDL reform（用户 2026-09-10 提出，尚未启动）

### 5.1 用户原文（照录，未改动）

> 现在有两个目标：第一个，让她有用，现在的节点多数是粗陋封装，且语义复杂，学习它们并将其链接起来形成workflow的难度不亚于学习pytorch本身，根本没有性价比，实际上它也是缝合产物，根本无法进行有效生产；让她快，有真正的算子融合、性能调优和profiling等等。
> 我的想法是：reform。
> 原来是：
> ComfyDL=Tensor+CV+RNN+Dataset+Regression+Misc，其中有不少的部分都是偷的d2l里的代码，
>
> 现在打算——直接对ComfyUI开刀：
> 现在我的构想：
> ComfyDL_UI
> =
> Comfy Core (KSampler, Image Tools, CLIP, Model Loader, ...，这些是ComfyUI本身开源提供的部分）
> +
> ComfyDL_Legacy (d2l(搬运的代码放到这里)+一些有用的节点，比如tensor、heatmap visu)
> +
> ComfyDL EX (能真的把计算图变成成品工作流的成熟可复用常见节点，粒度比现有的最基础算子要粗一些，比如：常用到的BatchMatMulMaxSum；Conv2d+滤波；能开箱急用、广泛调节各种参数、适配所有tensor并自动进行shape和存储方面诸如tiling、dbuf、fractal之类优化的真•万能全链接层节点--制作一个就够，等等。）
> +
> 性能优化（Graph Opt; Operator Integration; Profiling)
> +
> 为了适配深度学习生产而不是AI生图，进行适当UI改造

### 5.2 结构化理解（AI 整理，供后续讨论；未添加用户未表达的决策）

**两个目标**
1. **有用**：告别"粗陋封装 + 语义复杂"。现有节点把最基础算子做了浅封装，用户要拼出一条 workflow 的认知成本 ≈ 直接学 PyTorch，性价比低；且本质是搬运 d2l 代码的缝合产物，无法承担有效生产。
2. **快**：需要真正的算子融合、性能调优与 profiling 能力。

**手段 = reform（重构现有架构）**

- **旧结构**：`ComfyDL = Tensor + CV + RNN + Dataset + Regression + Misc`（大量代码搬自 d2l）。
- **新结构（直接对 ComfyUI 开刀）**：
  ```
  ComfyDL_UI
  = Comfy Core            (KSampler / Image Tools / CLIP / Model Loader …，ComfyUI 自身开源部分)
  + ComfyDL_Legacy        (d2l 搬运代码归档 + 仍有用节点：tensor、heatmap visu 等)
  + ComfyDL EX            (把计算图真正变成成品工作流的成熟可复用常见节点；粒度高于最基础算子)
  + 性能优化              (Graph Opt / Operator Integration / Profiling)
  + UI 改造               (面向 DL 生产，而非 AI 生图)
  ```

**各层含义**
| 层 | 定位 | 备注 |
|---|---|---|
| Comfy Core | 直接沿用 ComfyUI 开源自带节点 | 不再重复造轮子 |
| ComfyDL_Legacy | 旧 ComfyDL 的归档 + 有用节点 | d2l 搬运代码集中到此；保留 tensor、heatmap 可视化等仍有用节点 |
| ComfyDL EX | **新主力**：粗粒度、成熟可复用、开箱即用的"成品工作流"节点 | 例：`BatchMatMulMaxSum`、`Conv2d + 滤波`、**真•万能全链接层节点**（一个即够：开箱可用、参数广泛可调、适配所有 tensor，并自动处理 shape 与存储优化——tiling / dbuf / fractal 等） |
| 性能优化 | Graph Opt（图优化）、Operator Integration（算子融合/集成）、Profiling | 让工作流"快" |
| UI 改造 | 面向深度学习生产（而非 AI 生图）的适度改造 | 具体形态待定义 |

**关键转向**：从"教学/演示节点集合"变为"**DL 生产工具 + 计算图/算子级性能工程**"；节点粒度由"基础算子"上移为"可复用的常见组合算子"，把 shape/存储/tiling 等复杂性封装进节点内部。

### 5.3 与既有资产的关系（待确认的初步观察，非结论）

- `ComfyDL_Legacy` 大致对应当前内置的 **102 节点**（`d2l/*` 教学分类 + 并入核心的 utility/image 节点），可作为 reform 的归档基座。
- `ComfyDL EX` 属**全新层**，需新设计节点（尚无对应实现）。
- 性能优化（图优化/算子融合/profiling）与 UI 改造均为**全新方向**，与当前 ComfyUI 宿主能力需重新对齐。

> 上述落地路径、优先级、是否新建仓库/分支、Legacy 与 EX 的边界等均**未与用户确认**，待后续讨论。

### 6.2 Activation 详细要求

- 目标节点范围：**单输入单输出、无可学习参数**的激活函数（题中列出的应全部属于此类）。
- 每个激活函数做成一个节点：恰好 **1 个 input slot + 1 个 output slot**。
- 若有超参数：通过 **widgets** 控制，并设定**合理范围（如需）与默认值**。
- 逐项备注（仅登记，不落地）：
  - `Identity`：无参数。
  - `Softmax`：严格意义上是对某一维的归一化，通常需要 `dim` 超参（经 widget 控制）；其默认值与范围待定。
  - `Leaky ReLU`：通常有 `negative_slope`（负斜率）超参——是否存在、范围与默认值以最终设计为准。
  - 其余（Sigmoid/Tanh/ReLU/ELU/SELU/GELU/SiLU/Mish/Softplus/ReLU6/Hard Swish）多数无参，最终以设计为准。

## 9. 【更正 §7】「Comfy节点 / 扩展」的真实分组判据（2026-09-10 源码实测）

> §7 的**现象判断**（分类重复是我们把导入逻辑改乱）成立；但其中的**技术推论**（"不属于 `comfy` 库文件夹就不会成为 Comfy节点"→"必须篡改 `comfy` 库"）**被源码实测证伪**，现予更正。

### 9.1 结论

前端**不看**"代码是否位于 `comfy/` 文件夹"，而是看节点 `object_info.python_module` 的**首段模块名**是否命中白名单 `['nodes','comfy_extras','comfy_api_nodes']`。

- 前端 `getNodeSource()`（`penv/Lib/site-packages/comfyui_frontend_package/static/assets/api-D_pCbeK9.js`）：
  ```js
  const Pt = ['nodes','comfy_extras','comfy_api_nodes'];
  function getNodeSource(e, t) {
    if (!e) return H;
    let n = e.split(`.`);
    if (t) { /* essentials */ }
    if (Pt.includes(n[0])) return { type:`core`, className:`comfy-core`, displayText:`Comfy Core`, badgeText:`🦊` };
    if (n[0] === `blueprint`) return { ... };
    if (n[0] === `custom_nodes`) return { ... };
    return H;   // 其它 → type='unknown'
  }
  ```
- `settingStore-KkBYyEnh.js` 的 `classifyNodes()`：`nodeSource.type` ∈ {Core, Essentials} → 归入 **comfyNodes（Comfy节点）**；否则 → **extensions（扩展）**。
- 后端 `python_module` 来源：`server.py:765` `info['python_module'] = getattr(obj_class, "RELATIVE_PYTHON_MODULE", "nodes")`；该属性由 `nodes.py:574`（V1 `load_custom_node`）与 `nodes.py:602`（V3 Extension）写为 `"{module_parent}.{file/class}"`。

### 9.2 推论（本次 reform 落地依据）

- **把节点放进 `comfy_extras/` 并以 `module_parent="comfy_extras"` 加载 → 首段命中白名单 → 自动是「Comfy节点」，完全不需要改 `comfy/` 包。**
- 现状 `comfydl.*` 首段不在白名单 → `type='unknown'` → 归入「扩展」，这才是 d2l 出现在"扩展"下的**真实原因**。
- `CATEGORY` 字符串决定「Comfy节点」下的二级分组；空分类前端不渲染（故 `Network & Layers` / `ComfyDL EX` 暂不建）。
