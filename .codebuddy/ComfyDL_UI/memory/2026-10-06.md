# 2026-10-06 开发日志 — Profiling 四档日志系统 + M3 面板 Analyze/Expand 双 bug 排查

## 背景

用户报告 Profiling 面板两个症状：①点击「展开」按钮毫无反应；②点击「Analyze」后永远卡在 "Analyzing..."。用户要求先建四档日志系统（仿 pip -v/-vv/-vvv：off/low/medium/high，默认 off，启动参数或前端设置配置），以最高档手动测试回收日志定位问题。开工前完成日志/设置/启动参数三方面调研（结论已在本文件 §3）。

## 1. 初期猜想（静态代码检查，动工前记录，待运行验证）

### 猜想 A（高置信）：`renderOverlay()` 被调用但**从未定义** —— 两个症状的共同根因

`app/profiling_assets/profiler.js` 中 `renderOverlay()` 出现于 4 处调用：
- `requestOpgraph()` 内 **2 处**（约 L520 与 L535）
- `markOpgraphStale()` 内 1 处（约 L543）
- `setDisplayMode()` 内 1 处（约 L550）

但全文件只有 `mountOverlay()`（创建 overlay DOM）与 `renderPanel()`（向 sidebar 与 overlay 两个容器写内容）的定义，**没有 `function renderOverlay`**。JS 函数声明提升救不了未声明的名字 → ReferenceError。

### 猜想 B（症状②机理）：Analyze 卡死的精确链路

`requestOpgraph()` 的执行序（关键：L520 的 `renderOverlay()` 在 **try 块外**，try 从 L521 才开始）：

```
L517  state.opgraphLoading = true
L519  renderPanel()          ← 面板重绘为 "Analyzing..." + 按钮 disabled
L520  renderOverlay()        ← ReferenceError，且在 try 之外 → 直接抛出
L521+ try { ...fetch... }    ← 永远执行不到：fetch 从未发出
L533  state.opgraphLoading = false   ← 永远执行不到
```

→ loading 标志已置位、UI 已重绘、**重置代码被跳过** → 按钮永远停在 "Analyzing"（disabled）。这也解释了为什么服务端日志里根本没有收到 opgraph 请求。

### 猜想 C（症状①机理）：Expand 无反应的精确链路

`wirePanel()` 的 expand 处理器 = `mountOverlay(); setDisplayMode("overlay")`：

- `mountOverlay()` 在 `init()`（L1280）启动时就已执行 → `state.overlayEl` 已存在 → **early return**；
- `setDisplayMode("overlay")` → `renderOverlay()` → ReferenceError → 事件处理器中断；
- 结果：overlay wrapper 的 `cdlp-overlay-open` class 永远加不上 → 点了没反应。

### 预测（可证伪）

修掉 renderOverlay 后两症状应同时消失。若修后仍有异常，high 档日志会暴露：JS 未捕获异常、fetch 状态码/响应体、后端探针 per-node 错误。**验证结论见 §4（动工后补写）。**

## 2. 设计决定（四档日志）

- 档位 `off(0) < low(1) < medium(2) < high(3)`，语义：off=零输出；low=请求生命周期（开始/结束/耗时/汇总/4xx）；medium=逐节点探针结果（status/flops/probe_ms/error）+ 缓存命中；high=更细（payload 大小、缓存键、前端状态变迁、watchdog 轮询）。
- **后端**：新模块 `comfy/profiling/proflog.py`（纯 stdlib，仅惰性读 `comfy.cli_args.args`，绝不引入 torch——main.py 早期 import torch 是禁区）；启动参数 `--cdl-profiling-log {off,low,medium,high}`（默认 off）加在 `comfy/cli_args.py`；main.py **无需改动**（proflog 惰性读全局 args）。输出走标准 `logging.getLogger("ComfyDL.profiling")`（INFO 级）→ 自动进 `app/logger.py` 的 300 条环形缓冲 → `GET /internal/logs/raw` 可拉取。
- **请求级覆盖**：前端每次 fetch 带 `X-CDL-Profiling-Log` 头，`level_for(request)` 取 max(启动档, 头档)——头只能升不能降（排障时无需重启服务）。
- **前端**：官方 Settings API 注册 `ComfyDL.Profiling.LogLevel`（combo，默认 off，onChange 实时生效）；JS 日志 `plog(rank, msg)` 带 `[ComfyDL profiler]` 前缀；面板加「服务端日志」小卡（按需拉 `/internal/logs/raw` 过滤本组件行）。
- 顺带修复：`renderOverlay` 定义补上（wrapper class 切换）。
