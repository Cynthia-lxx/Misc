## 二、L2 占位节点重要性评估（应用户要求）

现状（`comfy_extras/nodes_model_inference.py` 实读 + 记忆）——6 个占位全是
"注册可连线、execute 即抛 RuntimeError"：

| 节点 | 依赖（被脱水删除） | 服务对象 |
|---|---|---|
| VAE Decode / VAE Encode | `comfy/ldm`（autoencoder 架构） | SD 图像生成管线（latent↔pixel） |
| CLIP Text Encode | `comfy/text_encoders` | SD 提示词→conditioning |
| CLIP Set Last Layer | `comfy/text_encoders` | clip-skip 截层技巧 |
| LoRA Load / LoRA Apply（nodes_model_merging 一侧） | `comfy/lora`（calculate_weight） | SD/大模型低秩微调 |

**结论：不是"至关重要"，建议不作为下一批次的主体。** 理由：

1. **服务对象错位**：这 6 个节点全部服务于 SD 式图像生成管线（VAE/CLIP/LoRA 都是
   Stable Diffusion 三件套的零件）。本项目当前主线是"从零教学 DL"→"DL 生产工具"，
   step6–9 的自研训练/LM 流水线（自建词表、TextEncode/TextDecode、NNMODEL spec 链）
   已经把"文本编码"这件事用自己的教学级实现走通了，CLIP 那套对教学是重复建设。
2. **解锁成本不成比例**：让这 6 个节点"转正"不等于补 6 个节点，而是要回捞
   `comfy/ldm` + `comfy/text_encoders` + 顺带 samplers/k_diffusion（有 VAE/CLIP 却没有
   采样器，管线仍然通不了）——这是"恢复 SD 能力"的战略级决策，不是节点批次。
   脱水清单 `docs/dehydrate_manifest.md` 有回捞安全网，随时可做，但应单独立项。
3. **唯一有独立教学价值的缺口是 LoRA 思想本身**：可以**不回捞** `comfy/lora`，为自研
   `NNMODEL` 写教学级低秩适配器节点（`lora_rank` 控件、A·B 分解、冻结原权重只训适配器），
   与 step6/step9 的训练闭环天然衔接（PARAMS/OPTIMIZER/Training Loop 都现成），成本低、
   教学价值高、零回捞依赖。

**给用户的建议（待选）**：
- 方案 A（推荐）：下一批次 = **教学级 LoRA**（新节点，~2 个：LoRA Wrap / LoRA Merge，
  作用于自研 NNMODEL，不碰 comfy/lora）；L2 六占位继续挂"接线占位"职责，等将来
  单独立项"恢复 SD 管线"时再原地转正。
- 方案 B：若用户真实诉求是"能出图"（SD 生成），则按 `dehydrate_manifest.md` 回捞
  ldm/text_encoders/samplers/k_diffusion 整链——工作量大数倍，需重新评估脱水战略。

交付内容：
- `comfy_extras/nodes_recurrent.py`（新文件、新分类 `Network & Layers/Recurrent`、入 extras_files
  白名单）：显式 cell 数学（GRU 重置门只缩放隐侧贡献，故输入侧/隐侧分开 `F.linear`；两 bias 相加
  同 `nn.RNNBase`；门行序 [i,f,g,o]/[r,z,n] 同 torch）；权重/bias/h0/c0 全走可选 slot，不连即零
  （只连 x 即可运行——无状态节点"开箱可用"的表达是不报错而非凭空初始化）；batch_first 固定、
  单层（堆叠 = y→x，续写 = hn/cn→h0/c0）、唯一控件 `hidden_size=16`；输出 detach。
- `TransformerDecoderBlock`（nodes_attention.py）：Self-Attn→Add→LN→Cross-Attn(k/v 来自
  context)→Add→LN→FFN→Add→LN，post-LN 与 EncoderBlock 同构；两组注意力权重+FFN 走 slot，
  cross_k/c_v 是 `(E, E_kv)`（context 宽度可不同），LN 仿射×3 可选；self_mask/cross_mask 用
  SDPA 布尔语义，接 CausalMask 即自回归。
- 上采样族（nodes_convolution.py）：`Upsample`（F.interpolate，mode 必须匹配 dims——1D=nearest/

- 软归档 `CdlRNNScratch/CdlRNN/CdlGRU`→`d2l/_Legacy/NLP Models`（DEPRECATED 三件套、id 不变；

## 五、step11 交付：实时预览（主仓 `8f2c829` / 子模块 `6bbdffd`，均已推送）

### 通道调研结论（用户提供 ComfyUI-original 源码分析，已核实并固化进踩坑 20 与设计文档）
实时预览官方通道 = `comfy.utils.ProgressBar.update_absolute(value, total, preview)` 的第三参，
格式 `("JPEG", PIL.Image, max_size)` 三元组。链路：节点 → 全局 hook（`main.py:hijack_progress`
经 `get_executing_context` 自动归属执行中节点，节点无需自己的 node_id）→ progress state →
WebSocket（新客户端 `PREVIEW_IMAGE_WITH_METADATA` JPEG 编码事件，旧客户端 `UNENCODED_PREVIEW_IMAGE`）
→ 前端按 node_id 渲染在节点下方。KSampler latent 预览即此通道，custom node 零侵入复用。关键细节：
**带 preview 的调用绕过 ProgressBar 自身节流（100ms/0.5%）总是立即发 → 绘图必须节点侧自行限频**。
备选路径评估：PromptServer.send_sync（需 hidden unique_id，重复造轮子）、返回值 ui 字段（静态、
事后才显示）、新 BinaryEventTypes（仅视频等新媒介才值得，需动 server+前端）。协议层不 import UI
机制 → 回调注入（`generate_tokens` 新增 `on_token` 姊妹回调，`progress` 原样保留）。
