## 2. 澄清后确定的约束（用户原话要点）

1. **空分类删除**：`ComfyDL EX` 从规划中彻底移除；`Network & Layers` 升级为真实父分类。
   全仓检索两个字符串均 **0 命中**（代码里从未存在，前端也不渲染空分类）→ 代码侧无删除动作，
   只同步文档与记忆。

# reform 第三步：归一化 + 训练/推理态通道（同日下午）

## 8. 需求

在 `Network & Layers` 下补齐第三个分支：**7 个归一化节点**（`Network & Layers/Normalization`），
并落地"训练/推理态 + 持久化运行统计量"的最小基础设施（`Network & Layers/Training`，2 个状态节点）。

- 动机：第二步后核心分支只有 14 个激活 + 8 个基础层，是完整的前馈栈，但**没有任何归一化**——
  归一化只存在于 ComfyDL 的模型级辅助节点（`d2l/Add & Norm`、`d2l/Transformer Encoder`），
  它们接收整个 `nn.Module`，**无法对图里一个裸 `TENSOR` 做归一化**。
- 第二个缺口：`BatchNorm`/`InstanceNorm` 在训练态与推理态算的东西不同，而 ComfyUI 没有全局"模式"
  概念、缓存图只在输入变化时重算 → 图里必须有一个**位置**来表达这个模式。
- 设计计划：`.codebuddy/plans/normalization-nodes-and-train-mode_1d443659.md`（**§3/§4 已过时**，见 §9）。

## 9. ⚠ 关键设计分歧：计划 vs 实现（下一位 agent 必读）

| 维度 | 计划（`.codebuddy/plans/normalization-nodes-and-train-mode_1d443659.md`） | 最终实现 |
|---|---|---|
| 状态节点如何被消费 | 两个"无 I/O 状态节点"通过 **hidden PROMPT 自省**被消费节点读取（读 `cls.hidden.prompt`） | **连线**：`TrainingMode` 的 `mode` STRING 输出 → 消费节点的 `mode` 插槽 |
| 缓存失效补偿 | 消费节点实现 `fingerprint_inputs`（含 hidden 的指纹并入签名） | 不需要——连线本身就在签名里（含祖先链） |
| 实例消歧 | `state_source` / `instance_name` 控件 + prompt key 作为机器唯一标识 | 无（改画布双击改名即可，零代码） |
| 统计量通道 | ① `TENSOR` 槽 → ② `RunStats` 的字符串 widget（经 prompt 自省）→ ③ 批统计量 | `TrainingRunStats` 节点把 widget 字符串**转换成 1 维张量**输出 → 走 ① 的 `TENSOR` 槽 |

**弃用 hidden PROMPT 方案的两条独立理由（均已核实）**：

1. **缓存签名看不到未接线的输入**。`comfy_execution/caching.py` 的
   `CacheKeySetInputSignature` 用 `class_type` + `node["inputs"]`（以及**所有祖先节点**的 inputs）
   生成签名；未接线的 hidden 输入两边都不在 → 翻转全局开关后消费者键完全不变，**图静默不重算**。
2. **算签名时它根本读不到**。两处正常执行之外的求值点（`IS_CHANGED` 与校验流程）调用
   `get_input_data(...)` 时 **`dynprompt=None`**（`execution.py:91`、`execution.py:1083`），
   隐藏 `prompt` 在那里是空字典；只有真正的执行路径 `execution.py:493` 才传 `dynprompt`。

**实现中这些机制一个都没有**（已 grep 核实，`comfy_extras/nodes_normalization.py`）：
`fingerprint_inputs` = 0 处、`state_source` = 0 处、`instance_name` = 0 处、
`resolve_training_state` = 0 处；唯一的 1 处 `Hidden.prompt` 出现在**模块 docstring 里说明为何否决该握手**（约 L28）。

计划文件顶部已加 ⚠ 废弃横幅，避免下一位 agent 照旧方案去找不存在的代码。

**为什么消费者侧用 STRING 而不是下拉**：`validate_node_input`（`comfy_execution/validation.py`）拒绝把
`STRING` 输出接到选项列表固定的 COMBO 输入上，下拉形态的插槽会拒绝这根连线；STRING ⇄ STRING 才能连通。

## 10. 实现

- 新文件 **`comfy_extras/nodes_normalization.py`**（910 行），并加入 `nodes.py`
  `init_builtin_extra_nodes()` 的 `extras_files` 硬编码白名单（漏加＝节点不注册）。
- 单文件承载全部 9 个节点：`comfy_extras` 无 `__init__.py`，跨文件 import 会在"独立加载 + 包导入"
  下产生双模块副本，故共享辅助函数必须与消费者同文件。

**7 个归一化节点**（`CATEGORY="Network & Layers/Normalization"`）：

| node_id | 显示名 | 输入（未标 optional 者必填） | 控件 | 语义 |
|---|---|---|---|---|
| `NormalizationBatchNorm` | BatchNorm | `tensor`, `weight`\*, `bias`\*, `running_mean`\*, `running_var`\*, `mode`\* | `eps` 1e-5 (0~1e-2) | `F.batch_norm`，通道维=dim 1 |
| `NormalizationInstanceNorm` | InstanceNorm | 同上 | 同上 | `F.instance_norm`，需 rank ≥ 3 |
| `NormalizationLayerNorm` | LayerNorm | `tensor`, `weight`\*, `bias`\* | `normalized_shape` `"last"`, `eps` 1e-5 | `F.layer_norm` 尾部维度 |
| `NormalizationGroupNorm` | GroupNorm | `tensor`, `weight`\*, `bias`\* | `num_groups` 1 (1~64), `eps` 1e-5 | `F.group_norm` |
| `NormalizationRMSNorm` | RMSNorm | `tensor`, `weight`\* | `normalized_shape` `"last"`, `eps` 1e-6 | `F.rms_norm`（LLaMA 风格） |
| `NormalizationWeightNorm` | WeightNorm | `weight`, `g`\* | `dim` 0 (-8~7), `eps` 1e-12 | `g·v/‖v‖₂` 重参数化 |
| `NormalizationSpectralNorm` | SpectralNorm | `weight`, `u`\*, `v`\* | `n_power_iterations` 1 (0~20), `dim` 0, `eps` 1e-12 | 除以幂迭代估计的 σ；**额外输出 `sigma`** |

**2 个状态节点**（`CATEGORY="Network & Layers/Training"`）：

| node_id | 显示名 | 输入 | 控件 | 语义 |
|---|---|---|---|---|
| `TrainingMode` | Training Mode | 无张量输入 | `mode` COMBO `train`/`eval`（默认 `train`） | 输出 `mode` (STRING)，供消费节点连线 |
| `TrainingRunStats` | Training Run Stats | 无张量输入 | `running_mean` `"0.0"`、`running_var` `"1.0"`（STRING） | 输出两个 1 维 `TENSOR`，供统计量插槽 |

消费侧 `mode` 插槽的确切声明（`nodes_normalization.py` 的 `_mode_input()`，BatchNorm/InstanceNorm 共用）：

```python
io.String.Input(
    "mode",
    default=MODE_TRAIN,      # 未连线 = "train"，PyTorch 默认
    optional=True,
    force_input=True,        # 纯插槽、不出控件：值本就该由连线传入
    tooltip="Link the mode output of a Training Mode node: ... Unconnected means 'train'.",
)
```

**贯穿三组核心节点的既有约定**（与 Activation/Basic 一致）：V3 `io` API、**无状态**（`weight`/`bias`/`g`/`u`/`v`
一律走 `TENSOR` slot，节点内不初始化、不缓存、**从不原地写入**——同一张量可能被多个节点共享）、
保持输入 dtype/device、**秩自适应**（不存在 1d/2d/3d 分支，`F.batch_norm` 本就能吃任意 `(N, C, ...)`）。

**统计量取值优先级**（由 `mode` 决定）：① `eval` + 线入统计量可用 → 用线入值；
② `train` → 忽略线入值、用本次批统计量（与 PyTorch 一致）；③ `eval` + 统计量缺失/不可用 → 回落批统计量并告警。
单值广播到全部通道（即默认 `"0.0"`/`"1.0"` 的效果），逐个通道的列表原样使用，个数既非 1 也非 C 则告警后走 ③。

**健壮性**（沿用前两步约定：不可用参数一律降级为有效结果 + `print("[Network & Layers] ...")` 告警，绝不中断工作流）：
rank 守卫（BN rank<2、IN rank<3、LN/RMS 0 维、WN 0 维、SN rank<2 原样返回；SN 同时 `sigma=0`）、
`num_groups` 不整除则用 1 组、`normalized_shape` 过期/乱码则按**维度个数**取实际尾部尺寸、
统计量个数不符则忽略、`dim` 按 rank 钳制、`clamp_min(eps)` 防除零、**全链路无 RNG**
（SpectralNorm 幂迭代初值取权重自身的行/列和 → 可复现、缓存安全）。
`_split_numbers` 兼容全角逗号/分号与空格分隔。

- **统计量优先级**：`eval` + 线入值 == `F.batch_norm(..., training=False)`；`train` **忽略**线入值 ==

- **数值**（全部对齐 torch）：LayerNorm `"last"`/`"8,16"`/过期 `"8,32"`/乱码 `"abc"` 四种情形；
  RMSNorm == `F.rms_norm`；GroupNorm（`num_groups=3` 对齐、`5` 不整除降级为 1 组）；
  WeightNorm（沿 `dim=0` 单位范数、乘 `g`）；SpectralNorm（确定性、20 次迭代 ==
  `torch.linalg.matrix_norm(W, ord=2)`、输出谱范数 == 1.0）。
- **rank 守卫**：IN 在 rank2、SN 在 rank1 原样返回（`sigma=0`）。
  注意：**BN 在 rank2 是合法的 `(N, C)` 输入、会正常归一化**，不要误判为 bug。

### ⚠ SpectralNorm 默认值的实测特性（待用户决策，见 §14-1）

默认 `n_power_iterations=1` 与 `torch.nn.utils.spectral_norm` 相同，但 torch 那个会把上次的 `u`/`v`
**热启动**，而本节点按设计是无状态的。实测（估计/真值）：

| 权重形状 | n=1 | n=5 | n=10 | n=20 |
|---|---|---|---|---|
| 6×5 | 0.996 | 1.000 | 1.000 | 1.000 |
| 64×64 | **0.706** | 0.893 | 0.970 | 1.000 |
| 256×128 | **0.783** | 0.933 | 0.985 | 0.998 |
