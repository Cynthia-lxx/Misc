# 2026-10-04 修复：ComfyDL 模板入口点击无反应（两个 LM 工作流入口）

## 一、背景

2026-10-02 在案的已知缺陷：Templates → ComfyDL → "Language Model: Train and Chat" /
"Load and Chat" 两张卡片**点击无反应**（工作流 JSON 本身已验证能跑）。用户当日提供

单路由），指示据此修复。

## 二、根因定位（前端 bundle 逆向实证）

在 `comfyui_frontend_package` 1.51.9 的 `settingStore-KkBYyEnh.js` 中确认三处逻辑：

1. **`sourceModule` 的来源**：store 的 `c` computed 把每个分类的 `moduleName` 原样拷进
   每张模板卡片的 `sourceModule` 字段；
2. **`fetchTemplateJson(name, source)`**：`source === "default"` 才
   `fetch(fileURL('/templates/<name>.json'))`，否则
   `fetch(apiURL('/workflow_templates/<source>/<name>.json'))`——后者是
   custom_nodes 专用通道（`custom_node_manager.py`，只扫 `custom_nodes/` 目录），
   comfydl 内置 overlay 根本不在其中 → 恒 404；
3. **`getTemplateThumbnailUrl(e, t)`**：同样只认 `t === "default"` 走
   `/templates/<name>-1.jpg`（`-1` 后缀**只在 default 时追加**），否则走
   `/workflow_templates/<module>/<name>.jpg`——即缩略图此前也是坏的。

失败表现链：404 → `.json()` 抛异常 → `loadWorkflowTemplate` 的 catch → **静默
return false** → 点击无任何反应。而卡片**可见性**由 `isEssential` 决定（侧栏 `l`
computed 对 essential 分类生成顶级 `basics-<title>` 导航项），与 `moduleName` 无关
——这就是「看得见、点不动」的组合成因。

我们的注入分类 `_COMFYDL_CATEGORY` 当时写的是 `moduleName: "ComfyDL"`（官方 index 里
所有分类都是 `"default"`），即一行之差。

辅助确认：`api-D_pCbeK9.js` 中 `fileURL(e) = api_base + e`（同源直连 `/templates/...`，
正是 overlay handler 服务的路由族）；`apiURL(e)` 会补 `/api` 前缀。

## 六、经验：PowerShell 下 cmd /c 嵌套引号会碎

- 本会话两次 `cmd /c "set "PATH=…" && …"` 突然被 PowerShell 按字面解析（嵌套双引号拆坏，
  `%PATH% && cd /d …` 整段被当成命令名）——此前同款命令多次成功，说明终端包装层路由
  不稳定，**不要依赖 cmd /c 嵌套引号**。
- 稳定替代：PowerShell 原生语法 + git 全路径 + `-C` 指定仓库：
  `& 'C:\Program Files\Git\cmd\git.exe' -C <repo> <subcommand>`（分号串联多步）。
  注意踩坑 12 说的「引号嵌套包 exe 全路径会失败」仅限 cmd /c 场景，PowerShell 的
  `& '…'` 调用没有该问题。此写法已实测成功，后续 git 操作优先采用。
