## A4. 必须记住的硬约束（方案据此定型）

1. **`execution.py:751` 用 `with torch.inference_mode():` 包住整轮 prompt 执行** → 跨节点 autograd 不可用，
   inference tensor 也不能参与反向（`Inference tensors cannot be saved for backward`）。
   ⇒ **前向 + 反向 + `optimizer.step()` 必须全在同一个节点体内**，循环也只能是节点内的 `steps` 控件。
   做法对齐上游 `nodes_train.py`：体内 `with torch.inference_mode(False):`、输入 `x.detach().clone()`。
   （本项目**没有**上游 `comfy_extras/nodes_train.py`，其 LoRA/扩散模型路线不可照搬。）
2. 跨运行状态一律走**连线**（既有铁律）：`PARAMS`/`OPTIMIZER` 都放 slot，超参放控件 → 缓存正确性白拿。
3. 输出张量全部 `detach()`，收尾 `optimizer.zero_grad(set_to_none=True)` + 逐参数 `param.grad = None`，
   **不把 autograd 图带进 Comfy 输出缓存**。
4. `seed` 同时决定初始化与批采样（`torch.manual_seed` + 局部 `torch.Generator`）→ 同输入同结果。
5. `loss=cross_entropy` 时校验 `y` 形态，不合法抛可操作 `RuntimeError`，**绝不静默降级**。

## B3. 前端补丁层 `app/frontend_patch.py`（NEW，11427 bytes）

唯一入口 `apply_frontend_patches(web_root: str) -> None`，调用点在 `server.py` 的 `PromptServer.__init__`：
前端根解析完成（`FrontendManager.init_frontend(...)` 或 `--front-end-root`）之后、静态资源被服务之前。
**实测启动日志**：`[Prompt Server] web root: ...\penv\Lib\site-packages\comfyui_frontend_package\static`

→ `[ComfyDL_UI] frontend applied 1 patch(es): about panel`（其余 3 项上一次启动已应用 → 证明幂等）。

设计约束（重要）：

- **按内容标记定位，绝不按带 hash 的文件名** → 前端包升级后补丁自动重新应用。
- **幂等**：每项在目标文件里写 `/*ComfyDL_UI:locale*/`、`/*ComfyDL_UI:nodes2*/`、`TENSOR:`#C6FF00``、
  `/*ComfyDL_UI:about:begin*/ … /*ComfyDL_UI:about:end*/`；已存在即跳过。
- **不阻塞启动**：每项独立 `try/except`，失败只打 ASCII 告警，服务照常以原版行为启动。
- **尊重 `--front-end-root`**：目标是解析后的 web root，不写死 `penv/...`。
- About 面板注入片段用的压缩变量名（`createElementVNode`/`toDisplayString`/systemStats store）
  是**用正则从被改文件里现抓的** → 前端重新压缩也不会错位。
- `_strip_about_section()` 先删旧注入再写新的 → 改文案只需改这个函数，下次启动自动替换（不是 append-only）。

# Part C：本次会话的工具/环境经验（高价值，勿再重复踩）

1. **git 不在本会话 PATH 里**。`where git` 找不到，但真身位于
   `C:\Program Files\Git\cmd\git.exe`（`Test-Path` = True）。
   可用写法：`cmd /c "set "PATH=C:\Program Files\Git\cmd;%PATH%" && cd /d <repo> && git status --short"`。
   （`cmd /c "... \"C:\Program Files\Git\cmd\git.exe\" ..."` 这种引号嵌套会失败，别用。）
2. **命令里的 `$` 会被外层包装吞掉**（PowerShell 变量 `$p=`、`ForEach-Object { $_.Line }` 都会变形报错）。
   → 优先用 `cmd /c` + `findstr`/`dir`；必须用 PowerShell 时**不要写 `$` 变量**，直接内联字面量。
   同理 `findstr` 的 `/c:"..."` 多模式引号在这条链路上会被拆碎，**一次只搜一个词**最稳。
3. **本工作区巨型**（`ComfyDL_UI` 5.9 万文件、`ComfyUI_Docs_Work` 6923 文件）→
   `search_file` / `search_content` 的递归搜索**容易 10s 超时**；定位文件优先用
   `list_dir`、`cmd /c dir /b /s <具体目录>`，或把 path 收窄到子目录再搜。
4. ~~**前端验收工作流**~~（`playwright-cli`，工作区 `.tmp_pwcli/`）——**⚠ 此法已停用，见 §D4：视觉验收改为用户自己做**。
   以下步骤仅作「万一用户要求我协助时」的备忘：
   `pcli.cmd eval <单表达式>`（一条命令只能一个表达式，**两段话用 `&` 串会因长度被截断，宁可分两次调**）、
   `pcli.cmd screenshot --filename x.png`；打开设置/About 面板后用 `screenshot` 存档。
5. **幂等补丁的验收要验「磁盘 + 被服务副本」两侧**（`verify_patches.py` 的 `*/served` 系列）——
   只看磁盘文件会漏掉「静态路由缓存了旧副本」这类问题。
6. **改前端前先记字节数 + sha 前缀**（`verify-after.txt` 末尾的 FINGERPRINT 行）——
   升级前端包后可以一眼判断「补丁有没有重放」。
